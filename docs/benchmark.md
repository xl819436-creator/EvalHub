# EvalHub 并发基准实验报告（Day 27）

- 实验日期：2026-08-29
- 数据来源：`docs/benchmark_raw.txt`（`scripts/benchmark_concurrency.py` 的直接原始输出，未做任何修改）
- 实验环境：Windows、Python 3.11.15（conda 环境 `evalhub-py311`）、50 条 Mock 评测数据
- 原则：本报告只记录本机实际运行得到的数字；没有测过的性能指标一律不写。

## 1. 实验方法

- 固定 50 条 Mock 评测数据，使用 Exact Match 评分；
- 每条用例模拟一次模型调用等待（`asyncio.sleep(0.01)`）；
- 数据集中 10% 的用例被刻意构造为失败（用于统计失败率）；
- 分别在并发度 1、5、10 下各运行一轮；
- 记录指标：吞吐量（条/秒）、平均延迟、P95 延迟、失败率。

复现命令（在仓库根目录、激活环境后）：

```powershell
conda activate evalhub-py311
python -m scripts.benchmark_concurrency
```

脚本直接打印 3 行结果；如需对照原始文件，请把输出重定向保存：

```powershell
python -m scripts.benchmark_concurrency | Tee-Object -FilePath docs/benchmark_raw.txt
```

## 3. 指标汇总

| 并发度 | 吞吐量（条/秒） | 平均延迟（ms） | P95 延迟（ms） | 失败率 |
|---:|---:|---:|---:|---:|
| 1 | 63.38 | 15.76 | 16.10 | 10% |
| 5 | 323.01 | 15.43 | 16.32 | 10% |
| 10 | 656.26 | 15.17 | 15.60 | 10% |

相对并发度 1 的吞吐加速比：

- 并发度 5：`323.01 / 63.38 ≈ 5.10` 倍；
- 并发度 10：`656.26 / 63.38 ≈ 10.35` 倍。

## 4. 结论

1. 并发度从 1 提高到 5、10，吞吐量近似线性提升（约 5.1 倍、10.4 倍），说明该批等待型任务可以被异步并发有效并行化。
2. 平均延迟基本稳定在 15–16 ms，与并发度关系不大。
3. **P95 延迟没有随并发度单调下降**：并发度 5 时 P95（16.32 ms）反而略高于并发度 1（16.10 ms），并发度 10 时又回落（15.60 ms）。P95 属于尾延迟，受调度、排队和资源竞争影响，单轮 50 条样本下波动正常——这也印证了"并发提高后 P95 不一定下降"。
4. 失败率固定为 10%，由数据集中刻意构造的失败用例决定，与并发度无关。
5. 以上所有数字均可通过第 1 节命令在本地复现；本报告不包含任何未实测的性能声明。
